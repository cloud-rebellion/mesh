# OpenAI Responses completion backend

This API backend is opt-in. Existing CLI, Anthropic and local backends retain their behavior. It uses a separately billed OpenAI API project, not a ChatGPT/Codex subscription or existing CLI login. Source implementation does not activate extraction or authorize a vault/pipeline job.

Choose `MESH_CURATOR_AGENT=openai` and supply **both** `MESH_CURATOR_KEY` and `MESH_CURATOR_MODEL` explicitly through the reviewed service secret/configuration boundary. There is no key discovery, `OPENAI_API_KEY` fallback, default model or OAuth-file access. Judge clients use their own `MESH_JUDGE_KEY`/`MODEL` (and JUDGE2/JUDGE3 equivalents); they do not borrow the curator key. `MAXTOK` is required and accepts only 1–32768, further limited by the explicit spending policy. Missing values fail closed. ENDPOINT and TEMP are refused for this backend. Never put a key in a note, transcript, repository, command argument or diagnostic log.

Every request is POST to the fixed public HTTPS `https://api.openai.com/v1/responses`. Redirects and private destinations are refused. Trusted system context is sent as `instructions`; the separate user/transcript input remains a user message. Requests send `tools: []`, `tool_choice: none`, `store: false`, `stream: true`, `max_output_tokens`, `service_tier: default` and `truncation: disabled`. There is no tool registry, executor, agent child or MCP access. This is the API route, not the separately restricted Sign in with ChatGPT route.

The closed SSE reader requires consistent response/item identities, event sequence, text and final output. The first sequence can be zero or one, matching primary examples; later sequence numbers must be consecutive. It rejects tool/refusal/unknown events, inconsistent failed/incomplete status, changed output, malformed/duplicate-key or noncanonical-property JSON, missing terminal and events after completion. Canonical lowercase ASCII property names prevent Go's case-insensitive decoder aliases from shadowing capability fields. It admits at most one reasoning item and one assistant text message; explicitly contradictory reasoning status is refused. Reasoning metadata is bounded and never returned or logged. Success requires an explicit completed terminal acknowledging tool choice none and storage false, followed by stream end. API capability/schema changes require a reviewed parser change; they are not silently enabled.

Bounds: combined system/user input 1 MiB; escaped request 7 MiB; stream 4 MiB; each event 256 KiB; returned text 64 KiB; 4096 events; JSON depth 32; absolute request deadline 120 seconds and idle-read deadline 30 seconds. Caller cancellation closes the request. Truncation, input/output limits and refusal are job-specific errors. HTTP 401/403 and narrowly identified authentication errors use existing ErrAuth semantics; 429/quota uses ErrRateLimited. Errors do not echo provider bodies, keys or prompts. There is no automatic retry, model switch, subscription fallback or paid-route fallback.

Before activation, approve the exact project/service-account role and key scope, permitted model, job/tenant/vault disclosure scope, concurrency/rate/spend admission, data/retention policy and runtime role boundary. A project-owned nonhuman identity can be limited to `api.responses.write` using the platform's current least-privilege controls. Keep administrative keys outside the worker. Model identifiers must be approved for that project; no model is assumed here.

`store: false` disables Responses storage; it does **not** by itself establish zero data retention, eliminate abuse-monitoring retention or change training/privacy terms. Review applicable account data controls. Alert thresholds are soft; current provider documentation also offers enforced organization/project caps with possible propagation overshoot. Token limits and timeouts do not establish a USD hard cap; enforce budget admission independently. A reviewed local-server fixture proves protocol handling, not real provider/model eligibility or production availability. A separately approved bounded real request and normal installed extraction journey remain required.

Primary documentation: [Responses](https://developers.openai.com/api/reference/resources/responses/methods/create), [streaming](https://developers.openai.com/api/docs/guides/streaming-responses), [service accounts](https://developers.openai.com/api/docs/guides/terraform/service-accounts), [data controls](https://developers.openai.com/api/docs/guides/your-data), [project limits](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform).


## Durable application spending admission

This separate source proposal reserves accounting units before any inference HTTP request. No rates, market model limits, budget amounts, pricing freshness intervals or billing project are selected by Mesh. Every OpenAI curator and judge prefix uses the one global `MESH_OPENAI_SPEND_DIR`; there is no per-prefix ledger setting. The deployment must ensure all processes using this account scope share that exact ledger on one host. Other users, providers, keys or hosts are not implicitly covered.

The operator must pre-provision a real private directory (0700, owned by the service UID) containing exactly `policy.json`, `state.json` and an empty persistent `lock` file (all regular, single-link, 0600, same owner). All ancestor components must be trusted real directories; a root-owned sticky temporary ancestor is allowed for private fixtures. No path links are followed. Linux and macOS use a kernel flock on the unchanged lock inode, bounded by caller cancellation (constructor wait at most five seconds). Other platforms refuse this backend; existing providers remain available when explicitly chosen.

Initialization is an explicit, separately reviewed operational action. The provider never creates a missing directory, policy, state or lock, never reinitializes a balance, and never rolls over a budget period. Filesystem locks, atomic rename and file/directory sync require a durable local filesystem with supported kernel lock semantics and healthy system time. Mode checks do not attest filesystem type, durability hardware or absence of extended ACL grants. These deployment properties still need actual metadata/acceptance before use. Shared/network filesystems and restored stale ledger copies are unsupported. The trust boundary excludes an operator or same-UID actor deliberately altering/replacing authorized files; use dedicated credentials and process isolation accordingly.

`policy.json` is a complete, bounded object with no omitted/null/default fields:

| Field | Meaning |
|---|---|
| `version` | Exactly 2; version-1 policy/state are refused, never automatically upgraded |
| `budget_id`, `scope_id` | Explicit stable safe identifiers for the budget and dedicated account/project scope |
| `currency`, `budget_nano_usd` | USD and a positive integer admission ceiling in billionths of a dollar |
| `period_start`, `period_end` | Explicit Unix-second budget interval; no automatic reset |
| `reviewed_at`, `valid_until`, `max_age_seconds` | Explicit review time, expiry and maximum evidence age; the current clock must satisfy every bound |
| `pricing_url`, `models_url` | Exactly the primary OpenAI pricing and model-documentation URLs named below; link strings establish provenance location, not factual verification |
| `all_input_charges_included` | Must be true: operator attests the input ceiling includes every applicable ordinary/cached/cache-write/long-context and regional/default-tier charge |
| `prefixes` | Unique explicit subset of MESH_CURATOR, MESH_JUDGE, MESH_JUDGE2, MESH_JUDGE3 |
| `models` | One to eight unique exact model policies; model strings must match both the configured and completed response model |
| `max_in_flight` | Explicit positive shared capacity, at most 128 (a representation bound, not a recommended value) |
| `min_admission_interval_ms` | Explicit positive shared admission spacing; no value is selected by Mesh |

Each model policy requires `model`, `service_tier` (exactly default), positive `context_tokens`, `max_output_tokens`, `max_input_bytes`, `input_tokens_per_utf8_byte_ceiling`, `framing_token_ceiling`, positive integer input/output nano-USD-per-token ceilings, and an explicit nonnegative `fixed_nano_usd_per_request_ceiling` (including explicit zero if reviewed). `max_input_bytes` cannot exceed the existing 1 MiB body-input bound; output cannot exceed 32768. The attested byte-to-token envelope plus framing and output must fit the stated context. That envelope is **operator evidence**, not a tokenizer or a universal text/token conversion proved by this code. Conservative limits must cover this exact request shape and selected model; leave the backend disabled if that evidence is unavailable.

Before HTTP, reserve:

```
context_tokens × input_nano_usd_per_token_ceiling
+ configured_MAXTOK × output_nano_usd_per_token_ceiling
+ fixed_nano_usd_per_request_ceiling
```

The full model context is reserved even for a short prompt. Token prices published per million must be converted to per-token nano-USD with upward rounding, including all applicable charges. Output ceilings must include long-context/other applicable pricing. No cached-input discount, success-only charging or visible-text token estimate is assumed. Checked integer multiplication/addition refuses overflow. This deliberately over-reserves and may admit fewer calls than the vendor would actually bill.

`state.json` requires all fields: version, budget_id, scope_id, policy_sha256 (SHA256 of exact policy file bytes), reserved_nano_usd, reservations, last_admission_unix, halted, last_admission_unix_ms, next_admission_unix_ms and outstanding_tickets (an explicit array, initially empty only through reviewed provisioning). An initial balance may be zero only through explicit operator provisioning. Any policy change invalidates both loaded clients and the existing state binding; it cannot silently reset prior reservations. Renewing policy/period or recovering a ledger requires a separate reviewed transition retaining the prior spend and unresolved outcomes. There is no reset/refund command in this provider.

The lock protects read/validate/check/reserve/state replacement across processes. A synced intent marker precedes the state write; the new state is synced, atomically renamed and its directory synced before the marker is removed and that removal synced. Failures before the replacement state and parent-directory sync complete retain intent/temporary entries and refuse fresh admission. If state and directory have already synced, intent removal succeeds and only its final directory sync fails, a private typed error identifies durably committed state with cleanup uncertainty. The current operation still suppresses success and marks that client unusable; a fresh process may see the committed state or a conservatively resurrected intent. This late phase does not imply lost state or mandatory shared refusal. No marker is recreated as a substitute for proven durability. Context cancellation bounds lock waiting and prevents later HTTP dispatch, but cannot forcibly interrupt an operating-system fsync; hung storage needs external process supervision, and no inference is dispatched while persistence is incomplete. Spending counters and the bounded outstanding-ticket array contain no prompts, keys or response text. Success is acknowledged only after durable accounting. Expiry is rechecked after persistence, and the HTTP context is bounded by the policy expiry as well as the original 120-second limit; an expired completed reservation remains charged.

Reservations are never refunded, including transport uncertainty, cancellation, authentication/rate errors, parser refusal and successful completion. Unknown/malformed usage yields no completion and retains the reservation. A well-formed completed response must report exact model/default tier and coherent nonnegative total/input/output usage within the reserved ceilings; missing fields, contradictory totals or excess/drift durably halt future use across prefixes/process restarts. A cancelled inference cannot cancel this separately bounded circuit-break persistence. Global admission failures use existing rate-limit/backoff semantics; prompt-envelope overflow remains job-specific. Explicitly selected invalid OpenAI judges return an unavailable client, never silently downgrade to CLI/local/self-grading. Callers may still queue ungraded material for human review; this is not publication authority.

This is an **application admission ceiling under attested pricing/context assumptions**, not a guarantee of the vendor's invoice. It cannot control other callers with the same account/key, provider pricing/model changes, provider billing errors, lost/rolled-back storage, privileged state edits, or transport retries outside this code. The provider itself performs no automatic retry. Selecting in-flight/spacing values, account/key/project binding, actual local storage/ACL durability, retention policy and a selected bounded real API fixture remain separate activation gates. `store:false` does not prove Zero Data Retention.

Current OpenAI documentation offers optional organization/project enforced spending caps but notes propagation overshoot; alert thresholds remain soft. Provider caps should be reviewed as additional controls, not substituted for this ledger. None is configured by this source proposal.

Primary references: [pricing](https://developers.openai.com/api/docs/pricing), [models](https://developers.openai.com/api/docs/models), [token usage and output limits](https://developers.openai.com/api/docs/guides/token-counting), [Responses parameters](https://developers.openai.com/api/reference/python/resources/responses/methods/create), [provider spend limits](https://developers.openai.com/api/docs/guides/spend-limits), [Go rooted filesystem operations and sync](https://pkg.go.dev/os).

## Shared dispatch admission (source preparation)

Schema 2 atomically commits the existing monetary reservation, one opaque outstanding ticket and the next-admission timestamp under the same immutable ledger lock. All configured OpenAI prefixes/processes must share this directory. No per-client quota, accumulated idle burst, background inference retry, model/key fallback, ledger initialization, schema conversion or account selection is added. Waiting releases the lock and is bounded by caller cancellation, policy expiry and the existing 120-second operation cap. Waiting owns no ticket and spends nothing. The state lock is not held during HTTP/SSE.

Each ticket records only a random 128-bit identifier, permitted prefix/model, admission time and request deadline. Outstanding tickets count against capacity even after their deadlines. A strictly validated completed, incomplete/max_output_tokens or supported failed response envelope can release the caller's exact ticket while retaining spending and pacing. The typed terminal requires coherent response identity, exact model/default tier, safe configuration, consistent supported terminal details, any reported usage within the admitted limits, valid output identities and complete stream checks. Failed/incomplete terminals return no completion. Bare HTTP status, EOF, a local ErrTruncated, parser failure, transport error or cancellation is not terminal proof. A locally proven cancellation before Do may release only that call's own ticket without refunding spend.

Unknown post-Do outcomes, process death and OS suspension retain tickets; no timeout/PID liveness/TTL reaping or restart reset occurs. A successful terminal release uses a separate bounded persistence context. Before-state-commit or state-directory-sync uncertainty refuses success and fresh admission through the retained intent boundary. A typed final marker-cleanup sync error after durably committed release still suppresses this operation and disables its client; fresh prefixes/processes may admit from the already durable released state, because terminal/pre-Do proof was earned before that mutation. A resurrected intent conservatively blocks instead. A late cleanup failure on initial admission retains the newly committed ticket and spending, returns no permit and never dispatches inference; it is not a reason to reclaim capacity. A recognized usage/model/tier mismatch still durably halts every prefix. Normal terminal failures recover capacity; unresolved uncertainty can exhaust capacity and needs an explicit separately reviewed reconciliation, not automatic state repair.

This is a single-host admission capacity and spacing control, not proof of provider cancellation, exact wire-time spacing, every RPM/TPM quota or vendor invoice correctness. Healthy clock, supported local durable filesystem, one shared dedicated account scope and conservative operator-attested spacing remain prerequisites. Scheduled callers can wait/retry whole passes under their existing semantics; the provider performs no paid retry. This unit does not implement a Retry-After cooldown controller or select fallback retry delays; a vendor refusal remains outstanding unless a strictly validated supported terminal proves generation ended. Further such controls require explicit review. Other hosts/account callers, stale restored ledger copies, same-UID edits and process pauses between admission and transport are outside the guarantee. See [official rate-limit guidance](https://developers.openai.com/api/docs/guides/rate-limits).

Version-1 evidence and spending are not erased. A future operational transition must retain the original policy/state bytes and all reservations/uncertain outcomes, explicitly provision the new schema and preserve any admission holds. There is no transition/reset/adoption command here. Current installed workers and historical jobs remain unchanged; compatible source/runtime and the separate selected-job/role/outbox/migration-maintenance gates still apply.
