# Mesh desktop shell

This source proposal provides a macOS-first native shell around the bundled Mesh Go engine. Its start screen creates app-managed vaults, opens human-selected existing vaults and shows local/offline state. Title search and bounded card selection open saved notes without requiring raw note IDs. The approved template catalog drives a native in-app editor; preview, validation, drafts and revision-fenced publication use the existing shared authoring tools. The existing graph/search/reader is served through the private application protocol in a sandboxed iframe.

Source preparation is on exact `783baede0366f125ef1f2a657f0d440f70f9eab9`. Only `mesh/desktop/**` is owned by this proposal. The matching engine is prepared separately. No application has been installed, signed for distribution, notarized, published or accepted for real automatic updates.

## Development and packaging

Electron **44.7.0**, `@electron/packager` **20.3.0** and `@electron/fuses` **2.1.3** were pinned from the official npm registry on 2026-10-08. The packaging dependencies require Node >=22.12. Dependency-free boundary tests can run on the existing Node20; that does not establish the Electron runtime or installer journey. Resolve with the checked-in Bun lock and install without unreviewed lifecycle execution; the Electron binary must be fetched through its pinned official distribution before native execution.

Run `node --test test/*.test.cjs` for source fixtures. Place the separately built `mesh-desktop-core` in `bundle/mesh-core/`, then run `node scripts/package-macos.mjs arm64 /absolute/pinned-electron-zip-directory` (or `x64`) with the supported packaging toolchain. The ZIP filename follows the official Electron release naming. The script verifies its exact official pinned SHA256 in a private copy and packages from those bytes without downloading a runtime or using the user's Electron cache. It checks the core's compiled identity, produces its SHA256 manifest, packages only shell source/renderer plus the core resource, enables ASAR integrity and disables Node/inspector/file-protocol escape fuses. Existing output is refused.

The temporary **unsigned review artifact** uses only keyless ad-hoc Mach-O sealing (`codesign --sign -`) after the packager's integrity patch and fuse changes. Apple Silicon otherwise refuses modified executables with invalid old seals. This is recorded as `distribution_signed:false`, `ad_hoc_runtime_seal:true`, signer `-`; no Developer-ID identity, key, notarization or distribution trust is used. The script never uploads, updates a channel or installs into Applications. Ad-hoc sealing does not establish signed update or distribution acceptance.

The provisional bundle identifier is `com.brightinteraction.mesh.desktop` and source app version is `0.1.0`. Both require final product/release review before signed distribution. Core and application versions remain distinct. Build provenance must bind the final managed source, required CI, exact toolchain and all bundle bytes, rather than merely trusting a source string reported by an unreviewed executable.

## Trust boundary

- BrowserWindow enables native sandbox/contextIsolation and disables Node, worker Node, subframe Node, webviews, arbitrary navigation/popups, downloads and permission requests. A private in-memory session permits only the fixed `mesh-app://desktop` shell and distinct `mesh-app://viewer` reader origins; no localhost listener or remote renderer is used. Distinct origins prevent the viewer from invoking the parent's privileged bridge; absence of a subframe preload alone would not provide this isolation.
- A narrow preload bridge exists only in the top frame. Every main IPC call checks the exact live window, WebContents, main-frame identity and fixed shell URL. No renderer paths, credentials, shell, arbitrary network, generic IPC or Electron objects are exposed.
- Only fixed static shell assets and allowlisted GET viewer routes are served. The transport filters response headers, imposes CSP and bounds bodies. Prior-vault responses are refused after a native switch. Graph/status filesystem paths must be removed by the matching engine.
- Main verifies a fixed bundled binary's SHA256 and exact protocol/version/source/platform/architecture identity before starting it. Bounded NDJSON runs over private stdio. Malformed/unsolicited/oversized replies terminate it; request timeout never automatically replays a write.
- Native app-data storage remembers opaque IDs/names; paths remain in main. Only a human file picker can adopt an external vault. Engine authoring/access/owner locks remain authoritative. A filesystem attacker in the same user account is outside this IPC isolation boundary; a signed bundle and private app-data permissions remain required.
- Existing credentials stay in the engine's private 0600 credential contract. The provider seam neither exports nor copies secrets and makes no Keychain claim. The native join screen requires confirmation, permits only the fixed Mesh HTTPS service and makes one explicit redemption attempt. Its source feature was enabled after review of the actual rendered form→native confirmation→real Go stdio→synthetic TLS download/search/offline recovery chain; this does not establish a real service invitation or role grant. The short invitation stays transient and is cleared after the attempt/cancel, with no credential export or persistence in the page. No browser handoff is reversed into native enrollment, incoming deep links/argv are ignored, and unknown roles remain unknown.

## Lifecycle and recovery

Switching vaults closes the old engine first. Application quit requests cancellation/drain and requests forced termination after bounded grace; if the operating system does not confirm exit, the app refuses closure/new ownership and reports the uncertainty. SIGKILL is not an unconditional termination guarantee. Child crash/timeout shows recovery instead of a success state. Local reads/writes need no remote connection; an unjoined local vault is labelled saved on this device, with offline availability and remote Sync disabled. Joined status reports pending changes/conflicts/last sync separately. Confirmed authoring and recorded successful synchronization refresh the fixed reader; a remote refresh is deferred while an editor is open. Sleep/resume triggers a status refresh, not an automatic uncertain write retry. Native close/switch must preserve or explicitly discard unsaved editor changes. Tool/status responses capture their engine/selected vault and refuse prior-context results; page session generations prevent an old save/editor/catalog response from changing the new vault. A prior-vault write may have completed even though its result cannot be applied here; inspect that vault before a new attempt. Missing/corrupt core bundles refuse vault startup.

The draft inbox lists bounded draft summaries and requests lossless structured content through the separately prepared shared `mesh_prepare_update {id,draft:true}` adapter. It retains draft identity/revision, evidence, audience and provenance; publication explicitly validates active content. The adapter passed actual real-Go native draft save/reopen/completion fixtures; the final managed source and release checks remain separate. Incomplete imported/untrusted authoring results are refused rather than parsed into a full replacement.

If publication is confirmed but its immediate revision reload fails, the editor retains the receipt and does not repeat the write. The next save reloads the published revision for review before another change can be submitted. Recovery remains tied to the selected vault; changing vaults clears the prior receipt and refuses its delayed response.

## Signed updater boundary

The updater is disabled with no configured signing identity, endpoint, key or publisher authority. Renderer URLs cannot configure it. Activation requires a reviewed desktop artifact contract, immutable versions, fixed authenticated HTTPS channel, content hash/size and source provenance, macOS signature/notarization checks, downgrade/collision refusal and safe drained restart/recovery. A VSIX or source-mirror publisher cannot publish a signed desktop release. No new signing or publisher capability is inferred here.

Acceptance requires a real signed installer and human/native journey: clean installation, personal vault, explicit existing vault selection, team enrollment with truthful principal, approved engineering/marketing/sales notes, edits/revision conflict, offline edit/quit/reopen/reconnect, preserved two-writer conflict, denied revoked remote access, and a second genuine signed version updating automatically. Windows/Linux are not claimed; Electron's built-in updater is macOS/Windows only. [Electron security](https://www.electronjs.org/docs/latest/tutorial/security/), [custom protocols](https://www.electronjs.org/docs/latest/api/protocol), [updater](https://www.electronjs.org/docs/latest/api/auto-updater), [fuses](https://www.electronjs.org/docs/latest/tutorial/fuses).

Actual native fixture evidence covers three template publications, graph/reader refresh, reader-to-editor selection, draft completion, cold restart, a controlled existing-vault picker, title selection, local-only saving, native enrollment cancellation, one redemption, downloaded search, offline reopen, uncertain cancellation and denial. All identities and invitations were synthetic; app data stayed under private temporary paths. The review bundle retains the Electron icon and is not a brand-ready public release.

### Disabled update and signing preparation

Application updates remain **disabled**: native startup still selects `configureUpdater(null)`, and every non-null channel configuration is refused. `PreparedUpdater` is isolated source preparation. It is not a release channel, signing executor, publisher, or an installed-update acceptance.

The future native-main provider requires an independently verified Developer ID / notarized installed app, an explicit architecture, a private durable version ledger, and an admission callback backed by the separately approved desktop publisher. A descriptor cannot approve its own source, configured applicable CI, team, or notarization claims. Existing Mesh source-mirror and IDE publisher grants confer no desktop authority. The signing account/identity and publisher are still absent. No renderer-supplied endpoint, credential, configuration or signing identity can activate this provider.

The descriptor contract is schema1, `mesh-desktop`, stable, darwin, bundle `com.brightinteraction.mesh.desktop`, numeric three-part app/core versions, exact40hex accepted source, architecture arm64 or x64 (core amd64), fixed10-character signing Team ID, notarization, exact archive size/SHA256 and independent approval/check-policy receipt digests. Metadata is limited to64KiB; ZIP256MiB, expanded512MiB,4096 entries and256MiB per entry. ZIP entry paths are limited to1024 bytes and64 components, with16384 total explicit/implicit namespace nodes counted in a component trie before full prefixes are allocated. The reviewed temporary Electron44.7 package inventory has602 entries/nodes,112-byte longest path and9 components; this grounds compatibility, not signed distribution acceptance. These are refusal bounds, not measured download/capacity guarantees. The proposed HTTPS paths on `mesh.brightinteraction.com` are fixed but unpublished/unconfigured. The downloader refuses redirects, ranges, non-identity encoding, foreign destinations, excess/short bodies and hash mismatch. It sends only an Accept header; vault authentication, invitations and browser state are not forwarded.

Before native staging, every canonical same-root ZIP entry is CRC-read with decompression bounds. Path aliases (including implicit ancestor components), duplicate case names, symlink descendants, special files, escaping/cyclic symlinks and overlapping/local-header disagreements refuse. Internal Electron framework symlinks are supported. Symlink targets resolve component by component before parent steps; an intermediate escape is refused even if later components would return inside the app. The root XML plist, actual core hash/Mach-O architecture, app executable architecture and app/core source/version mapping are checked. The private version ledger is flushed atomically and never overwrites a conflicting version slot; a residual writer lock refuses automatic recovery. ZIP64, non-ASCII paths and alternate app names are deliberately outside this first contract and require review rather than permissive fallback.

The main process writes private files, closes their writable handles, opens read-only handles, verifies identity/hash using positioned reads and unlinks their paths. Normalized JSON and admitted ZIP reach built-in Electron44.7/Squirrel only through held `file:///dev/fd/N` URLs. Existing native synthetic probes observed no-update metadata and invalid ZIP consumption; they did not stage a valid signed app. Source fixtures cannot establish signed native install, designated-requirement continuity, Gatekeeper/quarantine, read-only/translocated installation, privilege prompts, sleep/network recovery or both-architecture installed upgrades.

Native checking/staging begins only after an authenticated current-window/top-frame one-use restart acknowledgement freezes actual editor controls and reports dirty/active state. Unsaved notes defer unless the human explicitly discards them; Mesh never silently saves, publishes or replays them. Controller tracking independently refuses active tools, uncertain writes and unsettled enrollment, blocks new operations, drains the core and requires confirmed OS exit. Refused drain preserves editor buffers and the existing owner. An ordinary quit is separate: active requests defer closure, while unknown write/enrollment outcomes require explicit native confirmation. Quit retains that uncertainty, never replays it, blocks new operations and waits for physical engine exit before destroying the window. A canceled confirmation or unconfirmed exit keeps the window, editor buffers and owner. This path cannot bypass native staging/uncertainty locks. Durable author acknowledgements follow shared Go `toolWrite` receipts, including action/status, template/version, update identity/revision and index-stale success; an ID and revision alone are not confirmation. Historical `when` strings are retained as bounded metadata and are not required to acquire a new date for a durable update acknowledgement. After confirmed drain the UI remains locked through native staging; errors/timeouts stay uncertain with no automatic repeat. This matters because Squirrel can install an already staged update on any application termination. Its transactional replacement restores the previous bundle on installer failure; post-launch health and data rollback are not supplied. A recovery release must use a new higher app version and preserve vault compatibility.

`sign-macos.mjs` prepares a trusted-tool order and accepts synthetic output fixtures only. Its CLI refuses execution. Fuses/ASAR must precede signing; complete admitted inner executables/helper bundles are signed first, the signed core hash is bound, then the outer app is signed and verified, notarization must return Accepted, the app is stapled/validated, final signatures/Gatekeeper are assessed, and the final ZIP is hashed. The existing packager still performs only temporary ad-hoc sealing, never Developer ID signing or notarization. No synthetic receipt is distribution signing. Future isolated signer and publisher capabilities, complete entitlements/inventory, immutable publication admission and two genuine installed releases remain separate acceptance gates.

### Disabled scheduled discovery and quiet restart

The main-owned scheduler is source preparation and starts only after a real native-main provider has been accepted and configured. Current startup still supplies `configureUpdater(null)`, so it registers no update timer or controller listener and cannot perform a download or stage an update. Synthetic fixture signing flags, supplied admission callbacks and mock native events do not establish that authority. The missing Developer ID/account, installed-app identity proof, independent desktop publisher/channel admission and two genuine signed release journeys remain prerequisites.

With a future accepted provider, non-staging metadata/archive discovery begins after30seconds and normally repeats every6hours. Failures retry after1minute,5minutes,15minutes and then at most hourly. One task and one absolute deadline own the work; sleep/resume and clean-editor events coalesce, respect cooldowns and cannot enqueue missed intervals. Downloaded candidates use the existing strict fixed-origin HTTPS, source/size/hash/archive and immutable-ledger contract. Discovery accepts an optional AbortSignal: pause/quit destroys the active HTTPS request and response, removes its abort listener, awaits pending file writes and cleans its held bytes before completion. Cancellation does not certify a release or reset native staging/uncertainty.

An available candidate waits for the actual current-frame one-use editor acknowledgement. Automatic attempts never open a discard dialog, save, publish or clear unsaved buffers: dirty content or an active editor operation quietly defers. An internal automatic option preserves prior status only for that expected refusal before physical close starts; manual, unknown-write/enrollment, close and native failures remain visible. A later successful human draft save retains its normal confirmation. Only a later clean acknowledgement can proceed. The controller independently refuses active tools, uncertain writes and unsettled enrollment, freezes new operations, closes the original engine and requires confirmed OS exit before native staging. Unconfirmed exit or any acquired native staging/uncertainty halts scheduled attempts for the session; timers/resume cannot bypass it. No valid Squirrel staging was executed to prove this proposal.

Ordinary quit pauses and cancels discovery before draining the original owner; it waits for both. A refused quit resumes bounded discovery without repeating any note/enrollment operation or silently discarding editor state. Native update locks retain the previously reviewed hard refusal. This schedules the accepted preparation contracts; it does not establish an activated updater, a signed install, automatic distribution, post-launch health/data rollback or first/second release acceptance. Targeted Node source fixtures exercise actual main IPC/editor acknowledgement, controller ownership, cancellation cleanup and a synthetic NDJSON child’s physical OS exit. They do not substitute for a genuine installed Electron/Squirrel upgrade.
